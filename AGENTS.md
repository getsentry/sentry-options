# sentry-options

Sentry's internal option and feature-flag platform: schema-defined options, git-managed values, read at runtime. Values are validated, hot-reloadable, and backed by Kubernetes ConfigMaps. This repo holds the Rust and Python clients, the shared validation crate, `sentry-options-cli`, the `sentry-options-gen-stubs` pre-commit hook, and the reusable `validate-schema` workflow.

## Commands

- Rust format check: `cargo fmt --all -- --check`
- Rust lint: `cargo clippy --workspace --all-features --tests -- -D clippy::all`
- Rust tests: `SENTRY_OPTIONS_DIR=$PWD/sentry-options cargo test` (`.envrc` sets the variable)
- Python client tests, from `clients/python`: `uv sync --extra dev && uv run maturin develop && uv run pytest tests`
- Stub generator tests, from the repo root: `uv sync && uv run pytest`
- Pre-commit hooks: `pre-commit run --files <files>`

## Invariants

- Build the Python bindings (`clients/python`) with maturin, never `cargo build`. They are left out of the workspace `default-members` for this reason.
- Schema changes must follow the evolution rules in [docs/architecture.md](./docs/architecture.md#schema-evolution--validation). The `validate-schema` workflow enforces them.
- `CHANGELOG.md` is generated by craft at release (`changelogPolicy: auto` in `.craft.yml`). `scripts/bump-version.sh` sets the versions.
